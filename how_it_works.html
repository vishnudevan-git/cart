1 · At a glance

Lakrish Mart is a distributor-based B2B2C e-commerce platform. It is not one big shared marketplace — it is many independent storefronts, each curated by a distributor from suppliers they choose to work with.

What it does

  • Suppliers list products (with pack / variant sizes) and set a supplier price.
  • An optional Stockist adds processing charges and does physical picking & stocking.
  • A wholesale Distributor supplies many Marketplace storefronts and earns a margin.
  • Each Marketplace sets its own selling price and serves its own customers.
  • Customers browse, cart, order — and can also rent equipment from a real-money wallet.

Tech stack

  • Django 4.2 server-rendered templates + Django REST Framework.
  • Custom user model accounts.User.
  • SQLite for dev (db.sqlite3 / db_demo.sqlite3); PostgreSQL in prod.
  • django-axes login rate-limiting, WhiteNoise static files, Gunicorn server.
  • Pillow images, openpyxl Excel export/import, python-dotenv config.
  • A mobile delivery API (/delivery/api/…, token auth) for driver apps.
Settings module: lakrish_mart  ·  URL root: lakrish_mart/urls.py mounts each app under its own prefix (see §5). 13 apps are registered in INSTALLED_APPS.

2 · The core principle: everything is distributor-based

Recorded in DOMAIN_MODEL.md and baked into the code and managers.

  • Every storefront belongs to a distributor. A distributor picks which suppliers to connect to and which products to list.
  • A product is only ever shown inside a specific distributor's context — never in a generic listing.
  • A shopper enters a distributor's context by logging in or following that distributor's invite / store link.
Consequence for the public home page: without a distributor context there are no products to show — so the logged-out home page does not show a product grid or a search bar. It just leads with Login / Sign up. Product browsing happens after login or inside a distributor store.

3 · Roles — one account, exactly one role

Multi-role has been removed. An account can hold exactly one role at a time (changed by admin / transactions management, never stacked). Admin is not a customer — it has no shopping surfaces.

⚠️ Naming trap: internal code words differ from UI labels because of a mid-build rename. Both are shown below.

🅰️ Admin code: admin

The platform owner / “docking station”. The sole admin. Grants roles, approves products, sets commission, oversees everything.

🏭 Supplier code: supplier

Makes/owns goods. Lists products with multiple packs, sets supplier price, manages stock, sees restock requests & payouts. Granted by admin.

📦 Stockist code: stockist

Optional processing / pick-pack layer. Defines processing-charge stages, holds inventory, picks from suppliers, fulfils restock & procurement billing. Granted by admin.

🚛 Distributor code: wholesaler

The wholesale tier. Buys from one Stockist, supplies many Marketplace shops, earns a margin (per weight or per unit). Can create/reset its own shops. Granted by admin.

🏪 Marketplace code: distributor

The storefront (older UI label “Enterprise”). Owns a customer base; lists shared-catalog products and its own private products; sets selling prices; delivers; runs rewards & rentals. Granted by admin or created by a Distributor.

🛍️ Customer code: customer

Self-registers (optionally with a distributor invite code). Browses, carts, orders, earns reward points, rents from a wallet. The only role with shopping surfaces.

4 · The supply chain & how pricing is built up

Goods flow down the chain; money (margins) is added at each step. The final number a customer pays is the sum of everyone's markup, floored at cost.

The five links

🏭 Supplier→ 📦 Stockist→ 🚛 Distributor→ 🏪 Marketplace→ 🛍️ Customer

How the price grows (worked example from the price-flow test)

Supplier ₹200 → +Stockist charges → +Distributor margin → Marketplace sells. (₹/kg Distributor margin; Marketplace clamps between its cost floor and MRP.)

The Marketplace then adds its own margin and sells — e.g. it chooses ₹250 (margin ₹7). The customer's price is clamped: never below the cost floor, and never above the product's MRP if one is set.

The rules that shape each step

LayerWho controls itHow
Stockist charges Stockist Named stages (Shipping, Packing, Cold Storage…) with fixed ₹, % of price, or ₹/kg. Priority per stage: product > supplier > global.
Distributor margin Wholesaler (Distributor) Charged by weight (₹/kg) or quantity (₹/unit) — never a flat %. Applied on top of the stockist cost.
Marketplace margin Marketplace shop Per-product or a global %/₹-per-unit “Global Pricing”. Clamped to min(sell, MRP) then max(sell, cost floor).
Global Pricing gate: a Marketplace's pricing screens are locked until it configures Global Pricing at least once — this guarantees a sane default margin exists before products go live.

Special cases

  • Direct-supply products (e.g. eggs) skip the stockist and the wholesale Distributor: supplier → Marketplace. Neither earns a commission; cost = supplier price.
  • Marketplace own-products have no supply chain behind them — the price the shop types is the customer price.
  • Loose stock: a Distributor can hold bulk grams that any pack size draws from (e.g. 5000 g → 10×500 g).

Core function: stockist.models.get_stockist_price(product, variant, stockist, enterprise=None) returns the cost plus a full breakdown of every charge/margin.

Login routing (each role lands on its own dashboard): admin → /admin-panel/ · supplier → /supplier/ · stockist → /stockist/ · wholesaler → /wholesale/ · distributor → /distributor/ · customer → / (home)

Self-registration vs. granted: only Customer self-registers. Supplier / Stockist / Distributor / Marketplace are created by the admin (or, for shops, by their parent Distributor). See accounts.User.ROLE_CHOICES.

What happens at checkout

Price is locked. Each item's price is max(distributor_price, cost_floor) so the shop never sells below its true cost.
Stock is decided. If everything is in local (distributor) stock it becomes an express order; if only some is, and the shop allows it, it ships partially and back-orders the rest.
FIFO consumption. Available items draw from the shop's costed batches (oldest first).
Rewards & wallet. Reward points may be redeemed; on delivery, points are credited and auto-restock is checked.

Partial shipment: each OrderItem has its own fulfillment_status (pending / shipped / backordered / delivered / cancelled), and the order can be flagged is_partial_shipment.

8 · Money: commissions & automatic settlements

When an order is delivered, the platform works out exactly who is owed what and writes RoleSettlement rows. The math is derived from the frozen prices stored on each order line.

Where the money comes from

MarginFormula (per line)Earner
Supplier pricefrozen supplier_price × qtySupplier
Stockist chargebase_price − supplier_price × qtyStockist
Distributor marginincluded in the base/floor costWholesale Distributor
Marketplace margincustomer_price − base_price × qtyMarketplace shop

Commission rules

  • Rules are evaluated most-specific-first: product → supplier → overall.
  • Can be a % (overall/supplier/product) or a fixed ₹ (by price or by weight).
  • Direct-supply and shop own-products earn zero commission (no stockist / distributor in the chain).

Two kinds of balances — do not confuse them

🎁 Reward points loyalty

Earned after orders + manual adjustments. 1 pt = ₹1. Used as a discount. Lives in the distributors app.

💳 Wallet real money

Loaded with cash and spent on rent. A money ledger with credits/debits. Lives in the rentals app. The two never mix.

9 · Cross-cutting rules that show up everywhere

No hard deletes

“Delete” is always a soft delete — records stay with is_deleted / deleted_at and are admin-restorable. Default managers hide deleted rows.

Single-role logins

One account = one role. No role switcher. Admin is not a customer and never sees shopping surfaces.

Role-gated views

Decorators like @role_required(...) and customer_only guard every page; an audit crawl confirmed 0 authorization bypasses across ~140 gated URLs.

Isolation by managers

Shop own-products are hidden from suppliers, stockists, other shops, the storefront, and admin via Product.objects filtering — with all_objects as the deliberate escape hatch.

Auto-restock (safe by design)

When stock hits a threshold the system files a restock request — it never adds stock directly. A per-item opt-out and a price cap prevent auto-ordering expensive items.

Rentals master switch

The entire rent feature is gated by one admin flag, SiteSettings.rentals_enabled. Off → every rent page redirects home.

Also standard: CSRF on every form, django-axes locks a login after 5 failed attempts for 15 minutes, and production turns on HSTS / secure cookies / SSL redirect.

10 · How to run it locally

The project ships with an isolated virtual env (managed by uv) and an SQLite dev database.

StepCommand
Create envuv venv --python 3.11 --seed venv
Install depsvenv/Scripts/python.exe -m pip install -r requirements.txt
Create DB… python manage.py migrate
Run server… python manage.py runserver 127.0.0.1:8000

Config comes from a .env file (copy .env.example): SECRET_KEY, DEBUG, ALLOWED_HOSTS, optional DATABASE_URL (PostgreSQL). A demo mode uses a separate db_demo.sqlite3 and blocks real transaction writes.
